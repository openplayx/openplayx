# SMB 渐进读取（简单版）

SMB 播放启用按已读取字节推进的策略：首个 64 KiB 用 64 KiB 请求；累计读取达到
64 KiB 后升到 256 KiB；累计达到 320 KiB 后升到 1 MiB。请求仍受连接缓冲上限、
服务器协商上限和 SMB credits 限制。每个文件的最大缓冲保持 1 MiB，不反复重新分配。

网关首批输出也从 64 KiB 开始，随后最多每次输出 256 KiB，避免外层等满 256 KiB
才输出而抵消小请求的响应收益。SMB reader 与该请求的网关游标共用一个 `SmbReadRamp`，
只由 reader 按实际返回字节推进计数，避免两层重复计数。

每个 PlayableStream 独立保存最近四个读取游标，仅保留进度，不保存文件字节或文件句柄。
新 Range 的起点精确等于某个游标的下一字节时，复制其进度继续；其他位置从小块重新开始。
并行 Range、容器探测和旧请求各自使用独立的 ramp，不能相互重置进度。HEAD 和非法 Range
不会打开文件或推进策略。库内部同一文件句柄的缓存内定位直接使用缓存，缓存外定位重置 ramp。

HTTP 输出使用 `addStream` 传递背压及客户端断开，关闭输入生成器后由 `finally` 关闭 SMB
句柄。释放播放地址会立即标记当前请求取消。已经发出的 SMB 读取可能完成，但不建立无界
后台预读队列；客户端 TCP 断开的发现具有异步性。串行请求、认证、TLS 和签名设置不变。

这版不根据带宽自动计算块大小，不切换视频码率，也没有独立的多秒播放预读缓存。
固定读取仍是库的默认行为；只有 App 的 SMB 媒体播放通过 `open(file, readRamp: ...)`
启用渐进策略，附件等其他读操作保持原方式。

## 验证

- 库测试覆盖按实际字节升档、短读、缓冲上限、初始位置、缓存内外定位和克隆隔离。
- 网关测试覆盖首批输出不等待后续读取、相邻 Range 延续、非连续 Range 重置、并发探测、
  有界游标、HEAD、suffix Range、主动释放和客户端断开后的文件关闭。
- `tool/smb_progressive_benchmark.dart` 可使用仓库外的私有 JSON 配置，对固定模式与渐进模式
  的实际 HTTP 网关做真实文件对照。配置字段为 `host`、`username`、`password`、`domain`、
  `file`、`benchmarkSha256`（偏移 1 GiB 起连续 32 MiB 的 SHA-256），可选 `proxyPort`。
  配置和代理凭据不得提交，也不应上传 SMB 密码到 Relay。

```sh
dart run tool/smb_progressive_benchmark.dart /private/path/config.json
```

本机诊断使用与部署相同版本的独立 sing-box，固定 App 身份转发至 Relay 的 SMB 映射端口；
电影经完整 sing-box/frp/SMB 路径和 App HTTP 网关读取。实际手机、原生桥接调用和播放器解码
的首帧、拖动恢复仍需设备实测，HTTP 首批正文耗时不等于出画面时间。

## 真实电影对照（2026-11-12）

固定模式和渐进模式交替各测三次，每次完整读取同一偏移起的 32 MiB，取中位数：

| 模式 | 首批 HTTP 正文 | 持续读取 |
| --- | ---: | ---: |
| 固定 1 MiB 内部请求、256 KiB 网关输出 | 140.6 ms | 8.95 MB/s |
| 渐进请求、64 KiB 起步输出 | 47.5 ms | 8.73 MB/s |

首批正文等待降低约 66%，持续吞吐中位数相差约 2.5%。每次均核对完整 32 MiB 的 SHA-256
与 Home 本机直接读取结果一致；另验证五组 Range 数据、HEAD、相邻进度和跳转重置。
这些是短时样本，存在网络波动，不代表手机首帧保证。这里的首批正文计时包含 HTTP 请求和
SMB 文件句柄打开，不包含预先完成的 SMB 连接/认证，与只计 SMB READ 的首包指标口径不同。

库 20 项测试通过，App 250 项测试通过、6 项按原条件跳过；改动文件静态分析无问题。
