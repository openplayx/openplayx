# 远程访问三端配置管理

实现对应远程访问设计第 11 节。App、Relay、Home 各自拥有本端权威 JSON，不把完整配置自动同步到另外两端。

## App 设置入口

设置 → 远程访问：

- 查看草稿、已保存、实际生效修订，分别保存 JSON 与应用。
- 为已有 Jellyfin、Emby、Plex、SMB 来源导入配对，或使用类型化字段编辑代理、TLS 名称、公开 CA、家庭/服务/映射引用、局域网 HTTPS 端点与配对指纹。
- 每个来源最多配置四条备用线路，支持手动设为主线路；保存并应用后影响新会话。自动备用线路切换和播放中跨端点恢复仍不在本次实现范围。
- 编辑局域网探测超时、路径稳定窗口、播放前 TCP 建连重试和蜂窝使用偏好。
- 连接测试使用草稿来源和策略快照，不临时修改线上配置；只报告该草稿测试结果。
- 脱敏导出只包含公开连接参数、来源/家庭/服务引用和机密引用。

文件位于平台 `getApplicationSupportDirectory()` 返回的应用私有目录：

| 文件 | 内容 |
| --- | --- |
| `remote_access.json` | schemaVersion=1、revision、共享 lines、来源 bindings、policy；本端唯一可编辑远程配置 |
| `remote_access.backup.json` | 上一份已校验配置，无实际 UUID |
| `remote_access.state.json` | 只读的最近实际应用快照和错误，不提供独立编辑接口 |
| `remote_access.revision.json` | 已发放修订计数，损坏恢复也不复用旧修订 |
| `remote_access.lock` | 跨实例文件锁 |

线路公开参数在 `lines` 注册表中只保存一次；来源和备用线路通过稳定 lineId 引用，机密引用仍按来源隔离。同一线路 ID 的公开代理参数从设置页一起更新，不为每个来源另存一份可编辑代理地址。普通 JSON 禁止写 UUID、私钥或传输认证头，实际 UUID 保存在平台安全存储；旧版本完整 outbound 机密记录兼容读取，运行时以权威 JSON 的公开参数为准。

JSON 保存使用同目录临时文件、flush 和原子 rename，保存携带 expectedRevision。服务在进程内排队并使用操作系统文件锁，多个窗口或实例并发编辑会得到冲突而不是覆盖。修订可出现间隙但不会回退。

应用前检查配置结构、绑定来源、协议与凭据引用，并启动/关闭薄原生桥接实例验证内核能接受远程出站参数。Local-only 不启动远程内核。只有校验与状态持久化成功后才更新实际快照，新请求使用新设置；已有播放保留旧租约。应用成功不等于媒体认证或实际跨境线路已经测试通过。

当来源表单在同一次操作中更新媒体凭据与远程绑定时，SQLite 只保存远程管理标记和最低生效修订，不复制远程可编辑值。若配置已保存但应用失败，新请求在所需修订生效前保持阻止，重启后也不把新媒体凭据发送到旧端点或绕过代理。仍被期望配置、运行快照或备份引用的机密会被保留，取消未保存的编辑则清理临时机密。

### 策略边界

- 自动 LAN 仍要求系统信任 HTTPS 与配对证书指纹；不会扫描家庭网段。
- Android 使用 active NetworkCapabilities，iOS 使用 NWPathMonitor。禁止蜂窝时，检测到蜂窝或无法明确确认网络状态都会阻止远程新建连接；重新建连也检查，已经健康的播放不被强行中断。
- 后台 Flutter 引擎若没有网络类型桥接，也会保守阻止被禁止的远程连接，不会默认为 Wi-Fi。
- 连接重试只发生在发送应用请求前的 TCP 建连阶段，不重复提交密码、媒体登录或任意 Range。frp/VLESS 内部重连按各组件实际能力处理，不能把该设置理解为通用断流续播。
- 新增协议目前通过可信配对保留已有 VLESS/TLS/REALITY 公共参数；不是任意代理原生 JSON 编辑器。

## 旧数据迁移与恢复

读取旧 SQLite 来源配置中的 remoteAccess 后，先将绑定和公开代理参数持久化到 JSON，再清除成功迁移行的远程字段。来源 ID、配置修订和媒体资源身份不变，不改写未知或损坏的其他来源记录。媒体服务自身凭据继续使用原有来源凭据设施，与远程线路安全存储独立。

未知 schema、损坏 JSON 或运行快照不会用默认值覆盖；没有权威文件却出现旧状态文件时阻止连接。设置页提供明确的“恢复已知备份”：先另存原文件，再保存备份为更高的新修订；仍需另行应用。普通“恢复备份”也生成新修订。

## Relay 与 Home

两个仓库各有 `web/` 页面、`manager/` Python 轻量服务与安装脚本，复用已固定版本的组件生成/检查代码；无额外 Python 运行依赖。它们分别持久化 relay.json/home.json，机密值写入仅服务账号可读的 secrets.json，TLS 私钥使用受控目录资产引用。

页面包含类型化表单、登录、校验、草稿连接测试、保存、应用、状态、机密替换/清除、TLS 导入、恢复与脱敏导出。后端独立检查未知字段、schema、机密引用、端口冲突、重复服务、TLS 路径与 Home 授权。Web 无权导入更大 Home 授权、任意写文件或执行任意命令。

- Relay 默认 127.0.0.1:9081；Home 默认 127.0.0.1:9080。
- 首次初始化使用本机生成的 15 分钟凭据，无公共默认密码；随后设置独立管理员密码。
- 会话 cookie 为 HttpOnly / SameSite=Strict，HTTPS 时 Secure；写请求需要 CSRF token 与精确 Origin/Host，拒绝跨域。
- Home LAN 管理须明确监听并有管理员密码；Relay 非回环/公网管理必须同时配置 HTTPS。管理入口变化需本机重启管理服务，页面不把旧监听状态显示成已应用。
- 应用时执行真实上游配置校验，再生成 release 并切换 current；失败恢复旧运行路径且显示期望/实际修订差异。Home 先确认 SOCKS 就绪再启动 frpc，不提供直连回退。
- 损坏恢复需明确操作，并以原文件哈希检查冲突、保留原字节，生成单调递增新修订。

CLI 安装/更新也读取同一角色 JSON 和机密引用，使用同一锁，并在成功后记录实际修订。旧 deployment.json 只保留显式兼容导入，不再与 Web 配置并列编辑。新配对工具直接输出分离的 relay/、home/ 私有持久目录，家庭只取得其专属机密与证书；App 配对文件单独交付。

部署、迁移、管理服务安装及安全边界分别见 [Relay 配置说明](https://github.com/openplayx/openplayx-relay/blob/feature/remote-access-singbox-frp/docs/configuration.md) 与 [Home 配置说明](https://github.com/openplayx/openplayx-home/blob/feature/remote-access-singbox-frp/docs/configuration.md)。当前分支尚未推送时可直接阅读相邻本地仓库对应文件。

## 验证

新增测试覆盖 JSON 保存/应用区分、共享线路归一化、并发修订、单调损坏恢复、SQLite 迁移、机密清理、失败后跨重启阻止、设置页交互及 TCP 重建前策略检查。两个部署仓库测试覆盖管理认证、CSRF、跨域、脱敏、文件/端口/授权限制、修订冲突与应用失败回退。

Relay 的 `tests/e2e.py --managed-json` 使用真实固定版本 sing-box、frps、frpc 和 App 原生库验证角色 JSON → 机密引用 → 组件配置 → 认证/Range 媒体链路及访问控制。（2026-11-12 起该测试由 relay/home 仓库的 Go `TestEndToEnd` 取代，从角色 JSON 导入、经应用流程启动进程内组件，App 端改用同版本 sing-box 出站。）浏览器已实际验证 Relay 登录、草稿校验与“已保存但未生效”状态。Android APK 与 iOS 模拟器构建已验证新增网络类型桥接。

真实 Linux/systemd 安装、真实移动设备蜂窝切换、VPS 与跨境长期播放仍需环境验收；本次没有部署或公开任何实际服务。
