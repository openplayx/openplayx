# 画中画

播放器顶栏新增「画中画」。桌面小窗提供播放/暂停、还原和关闭；Escape
优先还原小窗。移动端进入系统画中画后隐藏应用控制层，使用系统的小窗操作。
需要重新构建原生应用，热重载不能安装平台通道和后台能力。

## 平台范围

| 平台 | 实现 | 限制 |
| --- | --- | --- |
| Android | 当前 Activity 的系统 PiP | 检测设备 PiP 能力；显式点击进入，不自动拦截 Home |
| iOS / iPadOS 15+ | AVKit sample-buffer PiP，来自当前 libmpv 解码器 | VLC 回退引擎没有对应输出，不显示入口；系统管理缩放、关闭和还原 |
| macOS | 当前独立播放器窗口切为置顶小窗 | 保存并恢复窗口位置、尺寸、样式、最小尺寸和全屏状态 |
| Windows | 当前独立播放器窗口切为置顶小窗 | 保存并恢复窗口 placement、样式和置顶状态 |
| Linux X11 | GTK keep-above 播放器窗口 | 保留系统标题栏用于拖动和关闭；窗口管理器决定置顶行为 |
| Linux Wayland / Web / tvOS | 不显示入口 | 当前未提供可保证行为的原生实现 |

桌面仅为独立播放器窗口注册通道，嵌在主界面里的备用播放器不缩小整个媒体库窗口。

## 状态与播放实例

`PictureInPictureController` 使用每个引擎自己的
`openplayx/picture_in_picture` 通道。进入请求准备阶段就标记 `entering`，
防止系统先发后台生命周期事件、再确认 PiP 时误暂停。原生 `changed` 事件决定
最终状态；请求失败恢复正常控件和后台暂停行为。
还原和关闭采用不同事件：还原先于前台生命周期回调时仍保持播放，
避免把正常还原误判为后台关闭。Android 以 `onStop` 作为不可见/关闭信号，
而不是只依赖此时可能尚未更新的 `isInPictureInPictureMode`。

切换不重新打开媒体、不创建新播放器，保留进度、播放/暂停、音轨、字幕和倍速。
移动端原有视频视图在切换中保持挂载，只调整布局和控制层。
关闭系统小窗且应用仍在后台时暂停播放，避免不可见的音频继续播放。
停止会话先退出 PiP；退出失败仍继续释放播放资源。

iOS 从 libmpv 的现有视频输出复制帧到独立 CVPixelBufferPool，再交给
AVSampleBufferDisplayLayer。进入 PiP 时切换为 CPU 渲染，避免后台执行 OpenGL ES；
输出限制在 960×540 内并保留比例。退出并回到前台后恢复原来的硬件渲染方式。
渲染器切换保留 Flutter texture ID，显式释放旧 mpv render context，
避免延迟的帧回调使旧渲染器仍占用上下文。PiP 的暂停/播放作用于同一个 mpv 实例。
当前 iOS PiP 为线性播放控制，不提供系统快进/快退。

## 验证

自动化回归位于 `test/features/player/picture_in_picture_test.dart`，覆盖：

- 视频视图和播放实例在切换、后台及还原时保持不变。
- 后台事件先于进入确认时继续播放；关闭小窗后恢复后台暂停。
- 请求失败恢复控件；不支持的平台和引擎隐藏入口。
- 桌面 Escape 还原；暂停视频也能通过按钮进入和退出。

仍需在各目标平台进行实际窗口/设备验收：播放视频后进入 PiP、切换应用、
移动缩放、暂停恢复、关闭小窗、还原全屏，并确认音轨和字幕没有变化。
iOS 的系统 PiP 动画、后台流畅性和设备功耗，Windows/Linux 的窗口管理器交互，
不能由 Flutter widget 测试或 Swift/Kotlin 静态编译验证代替。
