# 媒体库首版实现

对应目标设计：`../../../design/media/media_library.md`（工作区上层设计目录）。

## 使用入口

播放器顶部的「媒体库」按钮打开本机媒体库。界面参照 VidHub（见 `../../../design/research/vidhub-library-organization.md`）：不再创建库，媒体库就是所有已启用「文件源」的汇总海报墙。

文件源的管理放在底部导航的「来源」页：页面顶部左为「文件源」、右为「连接」两个并列标签，默认显示文件源。「连接」是原有的媒体源管理；「文件源」里点击「添加文件源」，依次选择已有来源连接、浏览并确认一个文件夹或服务端范围、为文件源命名，随后自动扫描。每个文件源可重命名、停用/启用、重新扫描或删除，另有「重新扫描全部」。媒体库页只显示汇总海报墙、搜索与筛选，没有文件源管理入口；没有文件源时提示去「来源」添加。来源账号仍在「媒体源」管理，不重复保存凭据。

支持本地、SMB、Plex 和 Jellyfin 的已有浏览/解析接口。扫描不下载视频、不启动在线刮削或 AI。普通文件保留原文件名与默认图标；服务端提供的电影、剧集、季、集与版本身份会保留。

## 已实现

- SQLite `library.sqlite3` 保存库、绑定、成员、手动成员证据、来源内容身份、资源与本机定位、忽略记录、扫描任务和观看进度。配置与凭据继续使用原有设施。
- 同一来源条目跨库复用媒体身份，服务端稳定内容 ID 聚合多个资源版本。同名文件不会根据名称合并。本机相同规范路径的直接播放和来源扫描复用资源与观看时间轴；多个本机定位保留为 locator。
- 文件源管理界面位于 `lib/features/sources/file_sources_tab.dart`，由 `SourcePage` 在传入 `LibraryService` 时作为第二个标签展示；媒体库页通过绑定状态是否为“扫描中”判断是否显示进度。
- 文件源（即绑定）带名称与启用开关；停用后其自动发现的媒体从海报墙隐藏，手动保留的成员不受影响，停用的文件源不会被扫描。界面不再提供建库入口，首次添加文件源时创建隐式默认库（`default`），旧版多库数据仍在汇总视图中显示，数据层与 AI 工具仍可操作多库。数据库版本升至 4（`bindings` 增加 `name`、`enabled` 列）。
- 支持最近加入排序、分页搜索、收藏、来源/内容类型/观看状态筛选。数据层另提供年份查询参数。
- 已有服务端季集按层级逐页浏览；缺失父级时仍可展示已有内容。不根据本地文件名伪造季集编号，不创建虚假的多集时间区间。
- 详情支持明确选择资源与来源、显示进度和可用性提示、修正标题以及从媒体库隐藏（移出所有库并写入忽略记录）。隐藏不会删除原文件、媒体记录、资源和观看进度。
- 删除文件源前展示关联数量。移除绑定只清除不再有其他绑定或手动证据的自动成员。
- 用户主动移除的内容写入忽略记录，重扫不重新加入；可取消忽略，并在下次扫描恢复。
- 持久化扫描批次、来源配置修订、目录队列与分页位置；失败后可继续同一任务。修改配置后创建新的扫描批次；分页不前进、异常身份和循环季集会失败并保留已有数据。
- 仅完整扫描成功后，才把此前发现而本次缺失的资源观测标为不可用。资源与用户数据继续保留。来源禁用或删除显示待配置状态，播放时重新解析来源并验证访问。
- 直接播放只登记最小身份与历史，不创建成员。资源进度按会话保存，旧会话不能覆盖新会话，支持向后跳转，不按最大进度合并。继续观看按内容展示最近资源的有效投影。
- 打开媒体后，在引擎报告可定位与有效时长时恢复同一资源的时间位置；切换版本不会沿用其他版本的进度。进度每五秒以及暂停、结束、切换和退出时保存。
- 身份登记与观看记录在后台完成，存储失败不会阻塞直接播放。解析后的临时播放地址与账号密钥不写入媒体库数据库。

## 当前边界

这是目标设计的本机核心版本，不代表全部设计规范已经完成：

- 尚无在线 Metadata/Artwork 插件、NFO/邻近封面与字幕导入、用户封面编辑或缓存维护，因此卡片目前使用默认图标。
- 尚无本地文件名的影视识别、跨来源作品匹配/合并撤销工具、资源内容指纹与文件替换修订检测。不同路径/编码不会仅凭同名合并；同路径文件被替换暂不自动区分内容修订。
- 未接入跨设备账号数据空间与同步、自动定时刷新、下载任务、字幕附件、书签、播放列表及 AI 工具网关。服务端进度不会自动双向同步。
- 播放可用性由实际来源解析决定；扫描观测与来源启用状态不是文件当前可播放的保证。本机直接文件的持久访问能力仍依赖操作系统授权。
- 进度保存暂与播放器页面集成，尚未单独抽出完整 PlaybackService/ProgressService；业务与扫描由普通 Dart LibraryService 承担，后续按新增能力拆分。

Widget 测试使用模拟播放与来源，未替代真实 NAS、Plex/Jellyfin 和原生 VLC 的设备验收。
